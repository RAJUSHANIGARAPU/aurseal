# Framework Discovery

## Plugin System

The wiki_project now includes a multi-tier AI plugin framework under `plugins/`.

### Structure

```
plugins/
  __init__.py
  _base_plugin.py      — BasePlugin ABC, PluginResult, PluginPriority
  cost_governor.py     — Budget tracking, model selection, prompt caching
  registry.py          — Auto-discovery of *.plugin.py files
  tier1/               — Foundational: unit-ai, integration-graph, api-contract, e2e-playwright
  tier2/               — Quality: visual-regression, security-scan, accessibility-a11y, mutation-testing
  tier3/               — Performance: load-performance, chaos-resilience, property-fuzz
  tier4/               — Novel: behavioral-equivalence, test-meta-quality, llm-output-oracle,
                         business-rule-compliance, state-machine-exhaustive,
                         synthetic-data-edge, temporal-regression
orchestration/
  __init__.py
  storage.py           — SQLite persistence (7 entity tables)
  master_orchestrator.py — Priority-tiered parallel execution + health scoring
  evolution_agent.py   — LLM-driven improvement proposals from run history
```

### Trigger Events

- `source_change` — unit-ai, property-fuzz, integration-graph, state-machine-exhaustive
- `dependency_change` — integration-graph
- `route_change`, `api_change` — api-contract
- `ui_change` — e2e-playwright, visual-regression, accessibility-a11y
- `deploy` — security-scan, business-rule-compliance
- `pre_deploy` — load-performance
- `test_change` — mutation-testing, test-meta-quality
- `pre_refactor`, `post_refactor` — behavioral-equivalence
- `manual` — most plugins

### Execution Model

1. CRITICAL plugins run sequentially — first failure stops the chain
2. HIGH plugins run in parallel (ThreadPoolExecutor)
3. NORMAL plugins run in parallel
4. BACKGROUND plugins run as daemon threads (fire-and-forget)

### Health Score Formula

- CRITICAL tier: 40% of score
- HIGH tier: 35% of score
- NORMAL tier: 25% of score
- Deploy threshold: health_score >= 70
