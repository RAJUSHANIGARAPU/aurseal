# Specs Directory — Planner → Generator → Healer Workflow

This directory contains human-readable test plan specifications (Planner output).
They map directly onto the three-stage test-agent workflow implemented in wiki_project.

---

## Workflow Overview

### Stage 1 — Planner (`web_discovery`)

The Planner explores the target application and produces structured test plans.
In wiki_project, `web_discovery` crawls pages, parses the DOM, and generates
scenario descriptions. The markdown files in `specs/` are the durable output of
this stage: human-readable, version-controlled, and editable by hand.

### Stage 2 — Generator (`core/ai/TestGenerator`)

`core/ai/TestGenerator` reads spec files and uses Claude to produce runnable
pytest + Playwright test files. Generated tests land in `ui/tests/` and follow
the Page Object Model with JSON-managed locators.

Run the generator via the autonomous loop:

```bash
python scripts/auto_runner.py
```

Or invoke `TestGenerator` directly from a Python script or Claude Code command:

```python
from core.ai.test_generator import TestGenerator

gen = TestGenerator()
code = gen.generate_from_trace()          # from a Playwright trace ZIP
code = gen.generate_page_object(...)      # from a spec description
```

### Stage 3 — Healer (`autonomous_ui`)

`autonomous_ui/healer.py` monitors test runs, detects broken locators or flow
regressions, and applies targeted fixes. It is invoked automatically by
`scripts/auto_runner.py` when tests fail.

## Spec File Format

Each spec file contains one or more scenarios. Use this structure:

```markdown
---
seed: false          # true for bootstrap specs that pre-date discovery
feature: <name>
---

## Scenario <short name>

### Preconditions
- Bullet list of state that must hold before the test starts
- Include navigation, auth, data setup

### Steps
1. Numbered action steps
2. Each step is one atomic UI or API action

### Expected
- Bullet list of verifiable outcomes
- Use concrete assertions (URL contains, element visible, text matches)

### Tags
`smoke` `regression` `<custom>`
```

### Frontmatter fields

| Field     | Type    | Required | Description |
|-----------|---------|----------|-------------|
| `seed`    | boolean | yes      | `true` = bootstrap spec, not generated by web_discovery |
| `feature` | string  | yes      | Short feature name, used as pytest marker |

---

## Running Tests Generated from Specs

```bash
# Full autonomous loop — runs all tests, heals failures
python scripts/auto_runner.py

# Filter to specs for a specific feature
python scripts/auto_runner.py -k "wiki_search"

# Dry-run: analyze failures without applying fixes
python scripts/auto_runner.py --no-fix

# Run with pytest markers matching spec tags
pytest -m smoke
pytest -m regression
```

---

## Adding a New Spec

1. Create `specs/<feature-name>.md` following the format above.
2. Set `seed: true` if you are writing the spec by hand before discovery runs.
3. Run `python scripts/auto_runner.py` — `TestGenerator` will pick it up and
   produce a test file under `ui/tests/`.
4. Review the generated test, adjust the spec if the output is off, then commit both.
